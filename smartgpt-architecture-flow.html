SmartGPT architecture

UI Capture, Database Retrieval, and Response Rendering Flow

This diagram follows the current Blazor server path in SmartGPT. It shows how a user's message is captured in the UI, persisted through the conversation store, enriched with live business data or cached context, composed into a response, saved again, and finally rendered back to the user.

Scope Message capture, chat orchestration, business data lookup, conversation persistence, response display, and history retrieval.
UI component Application service Conversation state API or database AI composition

Live Message Flow

Primary path from user input to visible SmartGPT response

How Data Is Captured

  1. 1 Browser inputThe user types a message, presses Enter, clicks Send, or attaches a supported file in InputBar.razor.
  2. 2 Composer objectInputBar.Send creates a ComposerSubmission containing message text, shortcut, and optional DocumentAttachment.
  3. 3 Layout orchestrationAssistantLayout.SendMessage blocks exhausted tokens, starts loading steps, and creates the display message.
  4. 4 User turn persistenceConversationState.AddUserMessageAsync adds the message locally and ConversationStore.SaveMessageAsync posts it to the configured conversation API/database.

How The Response Is Retrieved And Shown

  1. 1 Intent and data routingChatService.SendMessageAsync calls IntentService to decide whether to use live business data, cached data, general knowledge, document reading, export, quote creation, or prediction.
  2. 2 Database-backed resultFor data questions, ApiService.GetFilteredDataAsync posts filters to the business API, which retrieves quotes, risk notes, debit notes, or claims from the backend database.
  3. 3 Response compositionResponseComposerService converts raw JSON into user-facing text through an OpenAI-compatible response call when configured, otherwise it falls back to local summarization.
  4. 4 Assistant turn persistence and renderConversationState.AddAssistantMessageAsync saves the assistant response through ConversationStore.SaveMessageAsync, then ChatWindow.razor loops over Conversation.Messages and MessageItem.razor shows the response bubble.

Stored Conversation Retrieval Path

App starts or reloads AssistantLayout.OnInitializedAsync requests the user's saved conversations.
State requests data ConversationState.EnsureLoadedAsync gets the current user and asks the store to load history.
Store posts identity ConversationStore.LoadAsync sends company_id, user_id, system_id, and branch_id.
Conversation DB returns The API returns conversations[] with messages, cached API JSON, query parameters, and pending quote state.
UI displays history ChatSidebar lists threads. ChatWindow renders the selected thread's saved messages.

The repo also contains sample or runtime-looking files under App_Data/conversation-store, but the current ConversationStore implementation persists and retrieves conversations through configured HTTP endpoints.
